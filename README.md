# personal-portfolio

My personal portfolio site: a single static page with a light mission-control theme, built with [Astro](https://astro.build). No UI framework, just Astro components, plain CSS and a little TypeScript.

## Running it

Requires Node 22.12+.

```sh
npm install
npm run dev      # dev server at http://localhost:4321
npm run build    # static site in ./dist
npm run preview  # serve the production build
```

## Where things are

```
src/
  content/                all the copy: edit these to change what the site says
    site.ts               name, tagline, availability, resume and profile links
    about.md              About text and its opening statement
    clip.md               the climbing clip card in About
    projects/*.md         one file per project
  components/             the page's sections and cards
  pages/index.astro       the page itself: Nav, Hero, Missions (projects), About, Footer
  layouts/Layout.astro    <head>, fonts, metadata
  scripts/                client-side code: the rocket launch, the live footer readouts
  styles/global.css       design tokens and the few shared classes
  assets/
    projects/             images for the project cards
    brand/                generated by scripts/render-art.py; don't edit by hand
  content.config.ts       schemas for the projects and the clip
public/                   served as-is
  favicon.ico             tab icon fallback (browsers look for it here)
  preview-image.png       the picture shown when the site's link is shared
  assets/                 icons, plus the private files below
scripts/render-art.py     renders the brand art
```

## Editing content

**About text:** conventions for the statement, prompts and links are at the top of `src/components/About.astro`.

**Adding a project:** create `src/content/projects/<slug>.md` with `number` (the display order), `title`, `status` (`liftoff`, `in-orbit` or `decommissioned`), a one-sentence `summary` and a `stack` list. To show an image on the card, put it in `src/assets/projects/` and add a `display` block with `image` and `alt` (plus optional `position` and `zoom` to frame a busy screenshot). Set `draft: true` to hide a project. The build checks every field against `src/content.config.ts`.

## Files not in the repo

These are gitignored and mounted into the server's container at deploy time. The page works without them: the missing pieces hide themselves.

- `public/assets/Eli-Rose-Resume.pdf`: the resume the hero button links to
- `public/assets/climb.mp4` and `climb.jpg`: the climbing clip and its poster (paths set in `clip.md`). Both have the card's lit color grade baked in; see `ClipCard.astro`.
- `public/assets/status.json`: `{ "started": "<ISO date>" }`, written when the server starts; drives the uptime readout. Create one by hand to see it locally.

## Brand art

The name, the logo and the section headings are set in Mission Control DCU. Its license allows images of the font but not embedding it, so they're pre-rendered PNGs in `src/assets/brand/`. After changing any of them, re-run:

```sh
npm run art   # needs Python with Pillow and fontTools, and the font in design/fonts/ (not in the repo)
```

It also draws the rocket used in the logo, the favicons and the About card from one set of coordinates (writing its outline to `src/assets/brand/rocket.json` for the card), and renders `public/preview-image.png`, the picture chat apps show when the site's link is shared. That image takes its tagline from `src/content/site.ts`, so re-run the script after changing it.
